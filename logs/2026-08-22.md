# 2026-08-22 — SignalWire messaging: first delivered text, and what it cost

The shared number went from *one failed message ever* (Twilio, error 30034,
2026-07-21) to delivering texts end to end. Four commits shipped; three of the
bugs were only findable by actually running the rail.

## What actually blocked the number, in order

Six separate things, each invisible until the one before it was cleared. Three
of them fail **silently** — no error anywhere.

1. **A dead assignment record occupied the number.** Re-assigning returned
   `422 invalid_list_items` — *"Not available to assign within the project"* —
   until the FAILED assignment was `DELETE`d. "Just retry it" could never have
   worked, and the error message points at capability, not occupancy.
2. **No `status_callback_url` had ever been registered**, so the carrier's reason
   was never delivered anywhere. Re-created the order with one; the assignment
   reached `completed` in ~12 minutes.
3. **Inbound pointed at a dead staging Supabase project** and used
   `swml_webhooks`. Repointing needs handler *and* URL together — and SignalWire
   creates a **new** `cxml_webhook` Fabric resource rather than repointing the
   old `swml_webhook`, which is left orphaned (`6db2d8f3`, still pointing at
   staging).
4. **`sms_sender_numbers` was empty**, so every send returned `blocked_sender`.
   Its LIVE activation CHECK is far stricter than the first copy of the table in
   `schema.sql` — that file contains **more than one definition**; read
   `pg_constraint`, not the file.
5. **`accounts.high_value_lead_amount` was null**, and `Number(null) || 0` is 0,
   so `highValueThreshold > 0` made every lead non-high-value. No alert could
   ever fire. The field lives in a **nested** disclosure (Automations → Smart
   Intake → "Advanced"); setting it while collapsed silently does nothing.
6. **The service-area gate prunes `out_of_area`** and the served-city list is
   still the template default (Maplewood, Springfield, Oakdale…). A submission
   from a real nearby town is pruned to `low` and sends nothing.

## Proven, not assumed

- Outbound **delivered** (not merely accepted) twice: 11s and 22s end to end.
  `provider_accepted_at` and `delivered_at` are separate columns; a row that
  stops at accepted is the 30034 shape wearing a success costume.
- Inbound works — first ever. `STOP` flips the ledger **and** genuinely
  suppressed a qualifying high-value alert; `START` restored it.
- Callbacks delivered, stored, and **signature-verified 2/2**.

## The callback signature scheme (undocumented by SignalWire)

Solved offline against two captured `(body, signature)` pairs:

```
HMAC-SHA1(SIGNALWIRE_SIGNING_KEY, callback_url + raw_body) -> HEX
```

**Hex**, not the base64 the rest of the rail uses via `signBase64` — reusing
`validateWebhookSignature` here would reject every genuine delivery. The signed
URL includes the secret path segment, which is what makes verification possible
**without** migrating to a static path. Shipped measuring, not enforcing:
`LGQ_SIGNALWIRE_REGISTRY_REQUIRE_SIGNATURE=1` turns on rejection once real
traffic reads `valid` consistently.

## Mistakes worth keeping

- **Rotating the callback token is a carrier operation, not a config change.**
  The URL embeds the token, so rotation forces delete + re-create of the
  assignment. Doing it on a `completed` assignment broke it: the replacement
  failed **one second** after creation (vs ~12 minutes to succeed), and **no
  callback fired for that failure**. Only rotate when a failed assignment costs
  nothing.
- **The token leaked twice, identically.** A watcher captures the token at
  startup to build its redactor; rotate while it runs and it prints the new one
  verbatim. The fix is ordering — kill every watcher before rotating.
- **`sms_sender_numbers` can outlive the truth.** After the failed rotation the
  row still said `active`/`assigned` while SignalWire said `failed`, which would
  have sent on an unattached number. `scratchpad/sync-sender-truth.mjs` reads
  the provider and writes what is true.
- **A green pipeline and a broken feature coexist comfortably.** Every gate was
  green before the first text; the dead dashboard link and the inbox conflation
  were both only visible once a real message landed.
